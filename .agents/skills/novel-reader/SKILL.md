# 长篇小说读取

## 目标与边界
分块由程序完成，理解与资产抽取由 Agent 语义阅读完成。不得以正则／标题匹配冒称读懂小说。只读用户指定范围，百分比指转换后正文的字符范围并注明近似。

## 输入与输出
输入 TXT 或经 `doc-to-txt` 转换的文本、阅读范围和作品根。输出摘要、人物／场景／道具表、来源位置、事实时间线、未决信息和读取进度。

## 执行
1. 非 TXT 先转换并检查中文、段落和页面顺序。识别广告／感言等内容时由语义判断，并记录跳过的区间与理由，保留原文。
2. 使用 `scripts/read_chunks.py next --source <TXT> --state <进度JSON> --out <新chunk.json> [--end <范围末尾字符>]`。默认每块至多 3000 字符；中文偏移按 Unicode 字符计，附前 200 字上下文但不重复计算进度。
3. 阅读本块，提取剧情因果、人物外观／身份／背景／能力／出场、场景环境／作用／关联势力、道具外观／功能／历史／持有人。每条保留来源字符范围和短证据，原文未说明就写未知。
4. 合并同名／别名时核对证据，角色成长、换装、持有权变化记入时间线，不用后期设定覆盖早期事实。保留跨块待解的人物指代和伏笔。
5. 保存这一块的提取结果文件后，运行 `read_chunks.py commit --source <TXT> --state <进度JSON> --chunk <chunk.json> --result <提取结果JSON>` 才推进游标。result 为包含 `schema_version="1.0"` 的 JSON 对象，内容由 Agent 编写。
6. 下一块继续读；结束时给实际已读区间、未读区间、资产数量、重要冲突和改编可用片段。调用多块时逐块处理，不把几百万字一次返回到终端。

## 验收与恢复
文本偏移覆盖连续，未读内容不得写成已核实。输入哈希变化时拒绝接着旧进度读；创建新进度文件并重新对齐。脚本不会在 next 时提前推进游标；result 需先落盘再 commit，避免中断后漏读。

## 来源与限制
依据 [技能合集](https://bytedance.larkoffice.com/wiki/BdgQwEQPHi0EXckhyiOcT8cnn4c) 的 3000 字符、语义抽取和断点读取原则重建；块大小可调，不把所有模型上下文固定成 128k。
