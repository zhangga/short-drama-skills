# 短剧创作流程与设计说明

本套件围绕**故事开发、视觉资产、分镜、生成和剪辑**组织短剧制作，并提供内容审核、媒体验收和任务恢复支持。建议先用一个原创故事完成单集样片，再扩大制作规模。

设计参考：[《AI短剧漫剧创作 Skills 大合集》](https://bytedance.larkoffice.com/wiki/BdgQwEQPHi0EXckhyiOcT8cnn4c)。本项目提供 15 个职责明确的技能，以及文本读取、项目记录、结构校验、生成请求和媒体处理工具。

## 工作流设计

把剧本、角色／场景／道具资产、文字分镜与生成分开，能让问题有明确修改位置。素材与提示词本地保存、按集和 clip 整理、长期小说分段阅读，都适合反复迭代。角色参考图与场景参考图也比每段重新描述更易维护一致性。

具体动作、明确运镜和可观察的光线描述有助于执行。情绪目标仍有用：应在剧本／导演注释保留，再翻译成动作，而不是完全删除情绪信息。色温数字可选，位置、方向、软硬和昼夜关系往往更关键。

## 制作问题与处理方式

| 制作中常见的问题 | 对制作的影响 | 套件的处理方式 |
|---|---|---|
| 从一句故事直接推进资产与视频 | 有画面却可能没有人物动机、冲突升级和集尾悬念 | 总流程先产简报、大纲、剧本与故事审核 |
| 15 秒切成 15 镜，或在 1 秒内要求停留 3 秒 | 表演时间不足，指令时序矛盾 | 按动作／对白分配时长，脚本检查连续覆盖与超时 |
| 每个 clip 固定 15 秒 | 不同后端／模型／参考模式限制可能不一致 | 将其作为可调规划值，使用时核对实际模型 |
| 只验证图像文件存在 | 坏文件或人物／服装错误也可能被用于后续视频 | 完整解码、比例尺寸检查与视觉审看分开 |
| 断点续做主要依赖文件目录 | 提交超时或排队时可能重复生成和计费 | 保存输入哈希、任务 ID、状态与产物；unknown 先核查 |
| 强调生成大量单集 | 坏故事、坏角色会把返工扩散到所有集 | 先验证人物、场景和一段样片，再扩展 |
| 把生图型号偏好和“无水印”写成通用经验 | 产品版本、账号与实际服务行为不同 | 不固定个人模型排序，不承诺取消服务固有标记 |
| 用造型直接判定人物善恶 | 容易形成刻板符号，人物同质化 | 通过职业、经历、姿态、服装与道具表达人物 |
| 排队任务依赖 Agent 一直等 | 浪费执行资源，也不能保证自动续做 | 查询后留检查点；持续监控按用户需要另设 |
| 权限出错就切到非 Sandbox | 不解决真实账号／路径／权限原因 | 先诊断原因，不把放宽环境作为默认修复 |

提示词设计依据可观察的动作、摄影和灯光要求；生成接口依据当前官方文档与实际工具能力，不依赖对模型内部实现的推测。

## 建议实际创作顺序

受众与题材 → 核心冲突／人物关系 → 总纲与分集 → 剧本审核 → 文字分镜 → 人物／场景／道具卡 → 小段样片 → 全集生成 → 剪辑、对白、音效、字幕 → 故事与媒体审看。

分镜图只在需要构图预演或首尾帧控制时生成；无需为流程齐全给每镜都额外做图。图像后端任选一种，视频后端也任选一种，先把选定链路跑通，不必同时配置所有账号。

故事开发和剧本审核由 `novel-to-video` 统一组织；其余技能按任务需要调用。如果长期创作形成更细的编辑流程，可再把这些环节拆成独立技能。

## 实现范围与限制

创作类技能由 Agent 执行语义工作；脚本提供读取、状态、结构校验和媒体处理，不能自动评判好故事。生成类实现基础请求与结果记录；即梦采用实时 CLI 帮助适配，不能在缺 CLI 时制造假命令。所有付费后端未实测，需账号与用户实际模型权限。

每个技能保留独立触发场景、输入输出、执行、验收、恢复与来源。同一作品的进度／账本应由一个写入者维护；当前脚本不提供并发事务、供应商级幂等或无人值守生产保证。

接口参考：[Ark 图片](https://docs.volcengine.com/docs/ark/image-generation-api?lang=en)、[Ark 视频](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh&redirect=1)、[Gemini 图像](https://ai.google.dev/gemini-api/docs/image-generation)、[FFmpeg](https://ffmpeg.org/ffmpeg.html)。
